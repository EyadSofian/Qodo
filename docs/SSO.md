# الدخول الموحّد بين تطبيقات إنجوسوفت

_Single sign-on: the workspace as the identity provider._

المساحة هي **مصدر الهوية**. توقّع رمزاً قصير العمر لكل تطبيق، والتطبيق يتحقق منه
بالمفتاح نفسه ويفتح جلسة عنده. الفائدة الحقيقية ليست الراحة، بل أن **إيقاف موظف
واحد من صفحة المستخدمين يغلق عليه كل شيء فوراً**.

---

## ما وضع التطبيقات الأربعة فعلياً

قبل كتابة أي كود، فُحص كل مستودع. النتيجة مهمة، لأن الدخول الموحّد لا معنى له في
تطبيق لا يملك تسجيل دخول أصلاً:

| التطبيق | نظام الدخول الحالي | الوضع |
| --- | --- | --- |
| **تحليلات خدمة العملاء** (Next.js) | كامل: كوكي جلسة JWT + `/api/auth/login` + `createSessionToken` | ✅ **تم** — أُضيف `src/app/api/auth/sso/route.ts` |
| **أداء الأقسام (SLA)** (Express) | جزئي: `MANAGEMENT_PASSCODE` يحمي تبويب الإدارة فقط، واللوحة نفسها مفتوحة | ⚠️ ممكن، لكنه يمسّ منطق الجلسة القائم — يُنفَّذ بقرار منفصل |
| **الموارد البشرية** (خادم ثابت) | **لا يوجد** — `server.mjs` يخدم `dist/` فقط ويقرأ جدول Google عاماً | ❌ لا شيء يُربط به |
| **Insights Hub** (TanStack Start) | **لا يوجد** | ❌ لا شيء يُربط به |

> **لماذا لم يُضف شيء إلى الأخيرين؟** لأن إضافة الدخول الموحّد إليهما تعني إضافة
> **نظام مصادقة من الصفر** إلى تطبيقين مفتوحين اليوم. هذا ليس «سطراً يُضاف بلا
> ضرر» — إنه تغيير سلوك قد يمنع الفريق من الدخول صباح اليوم التالي. القرار قرارك،
> وإن أردته فهو عمل قائم بذاته لكل تطبيق.

## المفتاح المشترك

ضع القيمة نفسها في المساحة وفي كل تطبيق مشارك:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
```

| المكان | المتغيّر |
| --- | --- |
| Engosoft Workspace | `SSO_SECRET` |
| التطبيق التابع | `ENGOSOFT_SSO_SECRET` |
| التطبيق التابع (أصل المساحة) | `ENGOSOFT_HUB_ORIGIN` مثل `https://qodo-production.up.railway.app` |

المفتاح سرّي — في متغيّرات البيئة على Railway، لا في الكود.

## شكل الرمز

خوارزمية `HS256`، وعمره **خمس دقائق** فقط:

```json
{
  "iss": "engosoft-workspace",
  "aud": "support",
  "sub": "3f2b…",
  "name": "أحمد سيد",
  "email": "ahmed@engosoft.com",
  "role": "manager",
  "permissions": ["apps.view", "tasks.view", "…"],
  "iat": 1753400000,
  "exp": 1753400300
}
```

`aud` هو **مُعرّف التطبيق** في المساحة (`sla` / `insights` / `hr` / `support`).
كل تطبيق **يجب** أن يرفض أي رمز `aud` فيه ليس مُعرّفه — وإلا صار رمز HR صالحاً
لفتح لوحة المبيعات.

## المسار

```
المتصفح                   المساحة                        التطبيق التابع
   │                         │                                 │
   │ 1. POST /api/auth/sso/token { appId }                      │
   │────────────────────────▶│                                 │
   │◀────────────────────────│ { token }  (في الـ body، لا في الرابط)
   │                                                            │
   │ 2. POST https://<app>/api/auth/sso  { token }   credentials: include
   │───────────────────────────────────────────────────────────▶│
   │◀───────────────────────────────────────────────────────────│
   │        Set-Cookie: session=…                                │
   │                                                            │
   │ 3. يفتح التطبيق — الجلسة جاهزة                              │
```

**الرمز يُرسل في الـ body دائماً، ولا يوضع أبداً في الرابط.** الروابط تُسجَّل في
تاريخ المتصفح وفي سجلات الوسيط وفي ترويسة `Referer`.

## ١. جانب المساحة (جاهز)

```http
POST /api/auth/sso/token
Content-Type: application/json
Cookie: engosoft_session=…

{ "appId": "support" }
```

```json
{ "token": "eyJhbGciOi…", "expiresIn": 300, "audience": "support" }
```

يعيد `403` إذا لم يكن للمستخدم صلاحية على هذا التطبيق، و`404` إن لم يكن موجوداً.

في المتصفح:

```ts
async function openWithSso(app: WorkspaceApp) {
  const { token } = await api.post<{ token: string }>('/auth/sso/token', { appId: app.id });

  await fetch(new URL('/api/auth/sso', app.url).href, {
    method: 'POST',
    credentials: 'include',            // ليتمكن التطبيق من وضع الكوكي الخاص به
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ token }),
  });

  window.open(app.url, '_blank', 'noopener,noreferrer');
}
```

## ٢. جانب تحليلات خدمة العملاء (تم)

المسار: `src/app/api/auth/sso/route.ts` في مستودع `chatwoot_dashpoard`.

ما يفعله:

1. يرفض الطلب إن لم يكن `ENGOSOFT_SSO_SECRET` مضبوطاً — فالنشر الذي لم يشترك في
   الميزة لا يمكن الدخول إليه بهذه الطريقة.
2. يتحقق من الرمز بـ `jwtVerify` مع تثبيت `issuer` و`audience: "support"`.
3. يستدعي `createSessionToken()` **نفسها** التي يستدعيها تسجيل الدخول العادي،
   ويضع الكوكي نفسه بالإعدادات نفسها.

**لم يُعدَّل أي ملف قائم** — الملف جديد بالكامل، وتسجيل الدخول باسم المستخدم
وكلمة المرور يعمل كما كان تماماً. التحقق من الأنواع (`tsc --noEmit`) يمرّ نظيفاً
بعد الإضافة.

المتغيّرات المطلوبة على Railway لذلك التطبيق:

```bash
ENGOSOFT_SSO_SECRET=<نفس SSO_SECRET في المساحة>
ENGOSOFT_HUB_ORIGIN=https://<عنوان المساحة>
```

### ملاحظة على CORS

المساحة تنادي هذا المسار من أصل مختلف ومع `credentials`، فيحتاج ترويسات CORS
صريحة. ولأن `*` ممنوع مع `credentials`، ولأن إعادة أي `Origin` كما هو تجعل أي
موقع قادراً على تشغيل المسار — **لا يُسمح إلا بأصل المساحة المضبوط في
`ENGOSOFT_HUB_ORIGIN`**.

## ملاحظة مهمة عن الإطار (iframe)

عندما يُفتح التطبيق **داخل المساحة**، يصبح الكوكي في سياق طرف ثالث. المتصفحات
الحديثة **لا ترسل** كوكي `SameSite=Lax` في هذه الحالة:

| طريقة الفتح | الكوكي المطلوب |
| --- | --- |
| تبويب جديد | `SameSite=Lax; Secure` — يعمل |
| داخل المساحة (iframe) | `SameSite=None; Secure` — **إلزامي** |

`SameSite=None` يعني إرسال الكوكي مع أي طلب من أي موقع، فيجب تعويضه بحماية CSRF
(رمز في ترويسة، أو التحقق من `Origin`). إن لم يفعل التطبيق ذلك، اجعل طريقة فتحه
**«تبويب جديد»** من إعدادات المساحة — وهو الوضع الآمن الافتراضي.
