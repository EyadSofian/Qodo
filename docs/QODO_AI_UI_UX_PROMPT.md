# Qodo AI — UI/UX refinement prompt

أنت Product Designer وSenior Frontend Engineer تعمل على **Engosoft Workspace / Qodo**، وهي مساحة عمل عربية أولًا تجمع الداشبورد والمهام والإدارة وQodo Mail داخل نظام واحد.

## الموجود بالفعل

- Qodo AI متاح على مستوى الـWorkspace، ويستخدم بيانات النظام الحية فقط من الأدوات المصرح بها.
- أي كتابة أو إنشاء مهمة يظل Draft إلى أن يؤكد المستخدم؛ لا تغيّر بوابات الصلاحيات أو التأكيد.
- داخل Qodo Mail يظهر الـAI كـStory Card داخل تسلسل المحادثة، وليس Drawer أو تطبيقًا منفصلًا.
- عند فتح الكارت يبدأ تلقائيًا بتلخيص آخر 20 رسالة، ويمكن اختيار 10 أو 20 أو 40 أو 60 رسالة.
- نتيجة الملخص منظّمة إلى عنوان، ملخص، قرارات صريحة، وعوائق صريحة.
- الإجراءات الحالية هي: تلخيص، اقتراح رد، واستخراج مهام. اقتراح الرد يُنسخ إلى المحرر، وإنشاء المهمة يحتاج تأكيدًا.
- الواجهة تدعم RTL/LTR وDesktop/Mobile، وتستخدم هوية Engosoft الزرقاء الحالية.

## المطلوب

حسّن **UI/UX فقط** ليصبح أكثر وضوحًا وأناقة وسرعة في القراءة، مع إحساس اجتماعي حديث قريب من Stories/Instagram ولكن مناسب لمنتج أعمال احترافي. اجعل Qodo Mail جزءًا بصريًا طبيعيًا من Engosoft Workspace، لا تطبيقًا خارجيًا منفصلًا.

ركّز على:

1. وضوح مكان الملخص داخل المحادثة والتسلسل البصري بين الرسائل وكارت Qodo AI.
2. حالات الزر والكارت: مغلق، تحميل، نتيجة، خطأ، وإعادة المحاولة.
3. عرض العنوان والقرارات والعوائق كعناصر سهلة المسح البصري من دون ازدحام.
4. جعل اختيار نطاق الرسائل 10/20/40/60 واضحًا مع إظهار العدد الذي تم تحليله فعلًا.
5. Responsive حقيقي على الهاتف والتابلت وسطح المكتب، مع RTL عربي سليم وLTR إنجليزي سليم.
6. تباين وأحجام خط ومساحات ولمس وFocus states مطابقة لمعايير الوصول.
7. الالتزام بألوان ومكوّنات Engosoft الحالية، وتقليل الـgradients والظلال الثقيلة واستخدامها فقط لإبراز لحظة AI.

## قيود صارمة

- لا تغيّر أي Functionality أو API route أو request/response schema أو state flow أو permission/confirmation logic.
- لا تضف Features أو صفحات أو Navigation جديدة.
- لا تحذف إجراءات التلخيص أو الرد أو استخراج المهام، ولا تغيّر سلوكها.
- لا تغيّر ترتيب الرسائل أو منطق آخر 20 رسالة أو خيارات 10/20/40/60.
- لا تضف نصوصًا تسويقية أو عبارات دفاعية طويلة عن الخصوصية والبيانات.
- لا تستخدم تصميمًا عامًا منفصلًا عن Design System الحالي، ولا تجعل Qodo Mail يبدو كمنتج مستقل.

## المخرجات

ابدأ بتشخيص مختصر للمشكلات البصرية، ثم اقترح hierarchy وcomponent states وdesign tokens اللازمة. بعد ذلك نفّذ تعديلات العرض والـstyles فقط. اختم بقائمة Acceptance Criteria قابلة للاختبار على RTL/LTR وMobile/Desktop، وتأكيد صريح بأن الوظائف والـAPIs والصلاحيات لم تتغير.
