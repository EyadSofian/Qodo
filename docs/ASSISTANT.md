# مساعد المساحة — النموذج والأدوات الحيّة

_How the assistant knows the workspace._

## الخلاصة أولاً

لا ندرّب النموذج على بيانات الشركة الحيّة؛ ندرّبه فقط على اللهجة والسلوك واختيار
أدوات Qodo بدقة. المهام والموظفون والأرقام تبقى في قاعدة البيانات وتُقرأ لحظة السؤال.

النموذج الجاهز يعرف كيف يقرأ ويفهم ويجيب. ما **لا** يعرفه شيئان فقط:

1. ما لديك — ما هذه التطبيقات وما وظيفة كل واحد منها
2. البيانات نفسها — من المسؤول عن ماذا، وما المتأخر اليوم

وكلاهما **لا يُوضع داخل النموذج، بل يُرسل إليه لحظة السؤال**.

| الطريقة | يعرف بيانات اليوم؟ | التكلفة |
| --- | --- | --- |
| التدريب / Fine-tuning للسلوك | ❌ لا يحفظ بيانات اليوم — لكنه يحسّن اللهجة واختيار الأدوات | مرة عند الإصدار |
| RAG (بحث في مستندات) | جزئياً — جيد للنصوص، ضعيف للأرقام | متوسطة |
| **استدعاء الدوال (المستخدم هنا)** | ✅ نعم — يقرأ لحظة السؤال | منخفضة |

لو دُرِّب نموذج على مهام هذا الشهر، لأجاب الشهر القادم بمهام قديمة **وهو واثق أنها
صحيحة** — وهذا أخطر من ألّا يعرف.

## الدوال التسع

| الدالة | تعيد ماذا | الصلاحية |
| --- | --- | --- |
| `list_apps` | التطبيقات المتاحة للمستخدم ووصف كل واحد ورابطه | حسب تطبيقات المستخدم |
| `list_departments` | الأقسام ومراحل لوحة كل قسم | الجميع |
| `search_tasks` | بحث في المهام: متأخرة، لشخص، لقسم، بكلمة، بموعد | `tasks.view` |
| `task_summary` | أرقام مجمّعة وتوزيع على الأشخاص والأقسام | `tasks.view` |
| `list_team` | الأسماء والأقسام؛ الأدوار والإيميلات للمديرين فقط | الجميع (بتفصيل مختلف) |
| `create_task` | يضيف مهمة جديدة على لوحة القسم المحدد | `tasks.create` |
| `recent_activity` | سجل الحركة: من فعل ماذا | `users.view` |
| `insights_metrics` | مصروف الإعلانات والعملاء المحتملون والصفقات والإيراد | `apps.view` + وصول Insights |
| `support_metrics` | المحادثات وأوقات الرد والحل ومخالفات SLA | `apps.view` + وصول Support |

### الدوال تحترم الصلاحيات

كل دالة تستقبل المستخدم الحالي وتعيد التحقق من صلاحياته. المساعد **ليس** طريقاً
جانبياً حول نظام الصلاحيات:

- موظف عادي يسأل «أرِني كل مهام الفريق» ← يرى قسمه فقط، تماماً كاللوحة
- مدير يسأل عن الأداء أو المهام ← يرى قسمه كله، لا أقسام الشركة الأخرى
- مدير النظام وحده يستطيع القراءة على مستوى الشركة كلها
- موظف يسأل «من سجّل الدخول أمس» ← «سجل الحركة للمديرين فقط»
- موظف بلا `tasks.create` يقول «أضف مهمة» ← الدالة ترفض

هذا مطبَّق في `server/assistant/tools.js`، لا في الـ prompt — حتى لا يُلتفّ حوله
بصياغة ذكية من المستخدم.

## حدود المعرفة — والسبب

المساعد يرى بيانات المساحة نفسها، ويقرأ كذلك الأرقام الحيّة من Insights Hub
وتحليلات خدمة العملاء عبر أدوات مخصصة.

ما زال **لا يرى** سجلات الموارد البشرية الداخلية ولا لوحة أداء الأقسام (SLA)
لأنهما لا يقدمان واجهة قراءة للمساعد حتى الآن.

فإذا سُئل عن رقم موارد بشرية غير متاح فالإجابة الصحيحة:

> هذا الرقم داخل **الموارد البشرية** ولا توجد للمساعد واجهة قراءة له حالياً.

هذا مكتوب صراحةً في الـ system prompt مع تعليمة **«لا تخترع أرقاماً أبداً»** —
لأن نموذجاً بلا هذا الحد سيخمّن رقماً معقولاً ويقوله بثقة، وهو أخطر ما يمكن أن
يحدث في لوحة إدارية.

### الخطوة التالية: إكمال التطبيقين المتبقيين

لكي يجيب عن أسئلة الموارد البشرية وأداء الأقسام، يحتاج كل تطبيق إلى **واجهة قراءة
(API)** تعيد أرقامه المجمّعة. عندها نضيف دالة له:

```js
{
  name: 'support_metrics',
  description: 'Conversation volume, response times and SLA breaches from the ' +
    'Chatwoot analytics dashboard. Call for questions about customer support numbers.',
  input_schema: {
    type: 'object',
    properties: {
      from: { type: 'string', description: 'Start date YYYY-MM-DD' },
      to: { type: 'string', description: 'End date YYYY-MM-DD' },
    },
  },
}
```

والتنفيذ يستدعي التطبيق برمز الدخول الموحّد (انظر [SSO.md](SSO.md)).

| التطبيق | الوضع | المطلوب |
| --- | --- | --- |
| تحليلات خدمة العملاء | ✅ متصل عبر `support_metrics` | مراقبة العقد والصلاحيات |
| أداء الأقسام (SLA) | Express + Supabase | endpoint يعيد ملخصاً، أو قراءة Supabase مباشرة |
| الموارد البشرية | جدول Google عام | يمكن قراءة الجدول مباشرة عبر gviz |
| Insights Hub | ✅ متصل عبر `insights_metrics` | مراقبة حداثة المزامنة |

## التشغيل

```bash
# خيار OpenAI
OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-4o-mini

# أو Qodo AI المدرّب خلف endpoint متوافق مع OpenAI
QODO_AI_BASE_URL=http://127.0.0.1:8080/v1
QODO_AI_MODEL=qodo-ai-qwen3-1.7b
QODO_AI_API_KEY=qodo-local
```

بدون مفتاح OpenAI وبدون `QODO_AI_BASE_URL` تعمل المساحة كلها بشكل طبيعي، والمساعد
وحده يقول إنه غير مفعّل.

## حماية أدوات الكتابة

`create_task` لا ينفّذ مباشرة. الخادم يحفظ مسودة لمدة عشر دقائق ويرسل بطاقة تأكيد
للشخص المسجّل دخوله. التنفيذ يحدث فقط عبر `/api/assistant/confirm`، بعد مطابقة
المستخدم والمنظمة، ويُستهلك رمز التأكيد قبل التنفيذ لمنع تكرار المهمة عند إعادة الطلب.

ملفات التدريب والتقييم في [`ai/qodo-model`](../ai/qodo-model/README.md).

**لماذا العنوان واسم النموذج متغيّرات بيئة؟** لكي يمكن تبديل خدمة الاستدلال بين
الموديل المحلي وRailway أو مزود خارجي من دون تعديل الكود.

## تفاصيل تقنية

**البث:** الإجابة تُرسل حرفاً بحرف عبر SSE، وكل دالة تعمل تظهر للمستخدم أثناء
عملها («يبحث في المهام…»). سؤال يحتاج دالتين قد يستغرق ٥–١٠ ثوانٍ — وبدون هذا
البث يبدو الأمر معلّقاً.

**حلقة الدوال:** ست جولات كحد أقصى. إذا احتاج النموذج دوالّ بعدها، نتوقف ونطلب من
المستخدم تبسيط السؤال — بدلاً من حلقة لا نهائية.

**تجميع استدعاءات الدوال:** في البث، يصل استدعاء الدالة على أجزاء — الاسم في جزء
والمعاملات على أجزاء كثيرة — فتُجمَّع حسب `index` قبل التنفيذ.

**اللغة:** الواجهة ترسل لغتها الحالية مع كل سؤال، والنموذج يجيب بها.

**التكلفة:** السؤال العادي (سؤال + دالة + إجابة) يستهلك نحو ٣ آلاف رمز دخل و٤٠٠
خرج. على `gpt-4o-mini` ذلك أقل من نصف سنت للسؤال.

## لإضافة دالة جديدة

١. أضف التعريف في `TOOL_DEFINITIONS` — الوصف هو ما يجعل النموذج يعرف **متى**
   يستدعيها، فاكتبه بصيغة «استدعِ هذه عندما يسأل المستخدم عن…».

٢. أضف التنفيذ في `EXECUTORS` — وابدأ بفحص الصلاحية.

٣. أضف تسمية عربية وإنجليزية في `TOOL_LABELS` لتظهر في الواجهة أثناء العمل.

لا توجد خطوة رابعة — سيبدأ النموذج باستخدامها فوراً.
